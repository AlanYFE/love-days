# iPhone 实况上传

## 支持的入口

- 相册入口使用 `image/*,video/*`，避免枚举 MIME 导致系统选取器过滤；仍需 iPhone 真机确认。
- “从文件导入实况”不设置 accept 过滤，可选择 `.livp` 或照片与视频。服务端仍验证实际文件内容。
- 一次选择唯一同名 HEIC/JPG 和 MOV/MP4 时自动配对（忽略大小写），作为一张实况发布。重名冲突不猜测，改用手动补选。配对结果会显示在页面上。
- `.livp` 是包含一张 HEIC/HEIF/JPG 和一个 MOV/MP4 的 ZIP 包。当前只接受单组两文件包，拒绝混入其他文件、加密、路径穿越及超限解压。包内两份原文件保存，外层 ZIP 不保留；“原图”链接返回照片原文件。
- 取消“保留实况”只上传/保留静态部分。重新选文件会替换当前附件。

网页不能要求系统相册一定交出 Live Photo 的视频部分。如果相册只返回静态照片，请导入完整 `.livp` 或照片/视频对，也可以在苹果照片 App 中“存储为视频”，再用补选视频入口关联。单个 HEIC 并不保证包含动态。

## 真机验收

1. iPhone Safari 打开网站，点击记下今天，验证相册中 Live Photo 可选。
2. 若提示未检测到动态，不能把静态上传成功当作实况成功。
3. 从文件选择完整 `.livp`，或同时选择同名 HEIC/JPG 与 MOV。确认保留实况已勾选。
4. 发布后仅出现一张实况，打开大图点 LIVE，确认动态、方向和声音。
5. 再试取消保留实况，确认只有静态图，刷新后仍一致。

本地 API/浏览器验证不能代替 iPhone 系统选取器与真实 Safari 的验收。

2026-11-09 验证结果：31 项 Python 测试通过，1 项旧 OPPO 私有样本测试跳过；9 项 Node 测试通过；前端构建成功。390×844 的触屏 Chromium 使用真实本地 API 验证 HEIC/MOV 配对与 `.livp` 两条路径，均只发布一个 live 附件，且内联视频实际播放时间向前推进。未模拟 iOS 原生照片选取器。
