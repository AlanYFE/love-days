# Love Days · 快速试用版

两个人共同使用的私密照片日历。独立部署，不依赖 OpenAI 账号或海外前端 CDN。

## 已实现

- 手机适配的照片月历、全年蓝色热力图；一天一个格子。
- 热度按**发布记录数**计算：0、1、2–3、4–6、7+ 五档。照片封面下方的蓝色边条显示热度，避免蓝色蒙层盖住照片。
- 每条记录支持文字与多附件；支持补记旧日期。日期以用户选择的日期为准，不随服务器时区变化。
- 两个独立账号，共享全部记录；只允许删除自己发布的记录。
- JPG、PNG、WebP、GIF 图片与 MP4/MOV 视频；自动生成封面，原始图片保留。
- 登录后才能读取原图、视频与缩略图；密码使用 PBKDF2 哈希，登录限速、HttpOnly 会话 Cookie、请求来源校验。
- 上传进度、错误提示，每 30 秒刷新对方的新记录。
- 导出记录 JSON；服务器全量备份脚本。

这是已可运行的试用源码，**尚未部署到你的腾讯云账号**，没有公开网址。自动化接口测试与前端构建已完成；未做真实手机浏览器和中国大陆网络实测，Docker 部署流程未在本环境实机运行。

## 最快部署路线

### 1. 在腾讯云准备

1. 注册一个普通域名，按购买页面完成实名认证。域名购买后不需要转移给任何人。
2. 购买**轻量应用服务器 Lighthouse，中国香港地域**，选择 Ubuntu 24.04 LTS 系统镜像。试用建议 2 核 2 GB 起步、至少 40 GB 磁盘；最终以控制台可售套餐为准。暂时按月购买，先验证你们双方的网络。
3. 暂时不用购买数据库、COS、CDN、付费 SSL。试用版将照片、视频和 SQLite 存在服务器的 `data/` 目录。
4. 在服务器防火墙开放 TCP 80、443，SSH 22 尽量仅允许你自己的 IP。UDP 443 可选。**不开放 8000 和数据库端口。**
5. 在 DNS 解析添加 A 记录：主机记录 `love`，记录值为服务器公网 IPv4。
6. 最终地址形如 `https://love.你的域名.com`。如不配置 IPv6，请勿添加 AAAA 记录。

香港网站不走中国大陆服务器的网站接入备案流程，但跨境网络受运营商线路影响，不能保证每条国内网络都快。域名能注册不等于网络已经可访问；需部署后实际验证。

### 2. 上传和配置

通过腾讯云控制台 SSH 或自己电脑的 SSH 登录服务器。按 Docker 官方 Ubuntu 文档安装 Docker Engine 与 Compose 插件：
https://docs.docker.com/engine/install/ubuntu/

确认：

```bash
docker --version
docker compose version
```

把整个 `blue-days` 文件夹传到服务器，例如 `/opt/blue-days`。以下命令都在该目录中执行：

```bash
cd /opt/blue-days
cp .env.example .env
nano .env
```

将 `.env` 改为你的实际域名（不带 `https://` 和结尾斜杠）：

```dotenv
DOMAIN=love.your-domain.com
```

初始化两个账号。昵称与密码只在你自己的终端输入，不要发到聊天里：

```bash
docker compose build
docker compose run --rm app python scripts/setup.py
docker compose up -d
```

初始化脚本仅在没有任何账号时运行，防止意外添加第三人。第一次构建需要下载 Python 依赖、基础镜像和 ffmpeg。

Caddy 在域名解析正确、80/443 可访问时自动申请并续期 HTTPS 证书。等待启动后，在手机浏览器打开你的 HTTPS 地址，用刚才创建的账号登录。再给女朋友域名和她的账号。

**没有域名时**可以先在电脑上本地试运行；正式远程上传私密图片请等 HTTPS 配置好。这里只交付独立部署代码，不使用 OpenAI Sites 托管。

### 3. 上线检查

- 两台手机分别登录，A 上传照片与文字，B 在 30 秒内或刷新后能看到。
- 上传一段小 MP4，确认封面、播放、拖动进度正常。
- 退出登录后，直接访问原图地址应该提示未登录。
- HTTPS 无证书警告。
- 微信内打开和系统浏览器分别测试。微信可能对新域名提示风险，本站不能控制该提示；可先用系统浏览器访问。

### 4. 排查

```bash
docker compose ps
docker compose logs --tail=100 app
docker compose logs --tail=100 caddy
```

- 网站打不开：检查 A 记录、公网 IP、80/443、防火墙和域名拼写。
- 登录提示“来源不匹配”：检查 `.env` 的 DOMAIN 与打开的域名完全一致；更改后执行 `docker compose up -d`。
- HTTPS 申请失败：检查 80 和 443 端口以及错误的 AAAA 记录；不要短时间反复重建证书存储卷。
- 视频上传慢：先用较短 MP4 测试，再评估香港线路；不是购买更贵域名可以解决的问题。
- MOV/HEVC 不播放：浏览器编码支持不同，转成 H.264 视频 + AAC 音频的 MP4。应用不自动转码，只生成封面。
- HEIC：首版不支持，请导出为 JPG 再上传。
- 登录输错过多：等 15 分钟。首版仅两人使用，限速按代理连接 IP 共享计数。

## 本地开发

需要 Python 3.12、Node.js 20+，以及 ffmpeg/ffprobe（视频校验和封面依赖）。

```bash
python -m venv .venv
# macOS/Linux
source .venv/bin/activate
# Windows PowerShell 则使用 .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python scripts/setup.py
uvicorn app.main:app --reload
```

打开 **http://localhost:8000**，不要换成 `127.0.0.1`，否则需同步设置 `PUBLIC_URL`。

前端已经构建好，直接运行后端即可。修改 React 源码后：

```bash
npm ci
npm run build
```

前端入口为 `frontend.jsx`；样式在 `app/static/style.css`；后端在 `app/main.py`。无需注册 OAuth、微信开放平台或第三方数据库。

测试（测试库在临时目录，不影响实际记录）：

```bash
pip install pytest httpx
python -m pytest tests -q
```

## 备份、恢复与数据容量

**服务器磁盘不是独立备份。** 视频会占用空间，并消耗套餐流量。初版单文件上限 100 MB、每次合计 200 MB、最多 12 个附件；建议先上传短视频。按需求升级 COS 时需同时实现鉴权，不能简单把存储桶改成公开。

全量备份（会短暂停止应用，结束后自动启动）：

```bash
sh scripts/backup.sh
```

将 `backups/` 中的压缩包下载到自己的电脑或独立存储。包内含照片原文件、视频、缩略图、记录、账号密码哈希与会话，需私密保存。建议每周至少执行一次，或用自己服务器的定时任务调度脚本。当前交付没有替你开通任何定时任务。

首页“导出文字与记录清单”只有 JSON 和媒体相对链接，**不包含照片视频文件**，不能代替全量备份。

恢复到同样的应用目录时：先停止服务，为当前 `data/` 做备份并移走，再将备份包解压到应用根目录，使目录结构恢复为 `data/blue.db` 和 `data/media/`，然后 `docker compose up -d`。不要将旧备份直接覆盖混入一个正在运行的库。

升级前备份。不要删除 `data/`；不要将数据库、备份、`.env` 提交到 Git。

## 版本边界

- 一个固定双人空间，无公开注册、邀请系统或多人空间。
- 支持发布和删除，暂未提供编辑、回收站、找回密码、对象存储迁移和视频转码。
- 原始照片可能含拍摄位置等 EXIF；缩略图重编码。当前访问控制不是端到端加密，服务器管理员可以读取文件。
- 全年图保留照片缩略图和蓝色热度，手机上可横向滚动；月历默认优先显示照片。
- 没有内置收费或第三方统计，不调用 AI 服务。

## 评论更新

每个帖子下支持双方文字评论（1–1000 字），显示作者、日期时间，仅评论作者能单独删除自己的评论。删除帖子会同时删除全部关联评论。评论不增加热力图热度；导出的记录 JSON 和完整数据库备份都包含评论。

启动时通过 `CREATE TABLE IF NOT EXISTS` 增加评论表和索引，不需要重新创建账号，也不改写原有记录。建议升级前运行 `sudo sh scripts/backup.sh`，然后 `git pull --ff-only` 与 `sudo docker compose up -d --build`。前端构建产物已提交，无需在服务器安装 Node.js。

## 自定义表情与回应

首页“表情库”可上传共享的 JPG、PNG、WebP 或 GIF。表情原文件保存在 `data/emojis/`，需要登录才能访问，GIF 保留动画。单个最多 5 MB、最长边 2048 像素、最多 200 帧、总解码像素 8000 万，库容量 100 个。名称可填写，留空时使用文件名。

评论可包含文字和最多 8 个表情，也可只发表情。在帖子或评论下点击“☺ ＋”选择回应，点击已有回应加入，再次点击取消自己的回应；同一用户对同一目标的同一表情仅计一次，不影响对方。回应显示人数，自己选过的呈蓝色。评论与回应不增加热力图热度。

更新自动新增表情、评论附件及回应表，无需重建账号。删除帖子会级联删除其评论及所有关联回应，但保留共享表情库；删除评论会级联删除该评论的表情引用及回应。全量备份会包含 `data/emojis/`。此版本不提供共享表情删除或改名，以免影响历史引用。前端已构建，更新仍使用 `git pull --ff-only` 和 `sudo docker compose up -d --build`。

## 共享标签

- 发帖或编辑自己的帖子时，可搜索、多选或创建标签；每条最多 8 个，单个名称 1–24 字，共享库最多 200 个。
- 两人使用同一个标签库。名称会统一全角/半角和空白，并按大小写不敏感方式去重；不会自动合并语义近似的名字。
- 创建标签立即保存到共享库，取消发帖后标签仍保留；取消选择只解除该帖子与标签的关联。
- 旧帖子默认没有标签，可在编辑时补充。旧客户端不传标签字段时保留原关联。
- 标签编辑与文字、日期一并提交；冲突检测覆盖标签，保留原附件、评论和回应。
- `tags` / `entry_tags` 表启动时自动创建，备份 data 目录即可包含标签；导出的帖子包含标签 ID 和名称。
- 为未来按记录日期和标签统计预留独立关联表；当前尚未提供统计页面、标签重命名或标签库删除。


## 实况照片（网页试用版）

- 发帖选图后检测 JPEG Motion Photo 标记，显示“保留实况”；实际动态以服务端验证结果为准。
- 已用 OPPO OLivePhoto v2 原始样本验证内嵌主视频提取、音频、H.264 网页播放版本和原图留存。播放使用主视频，不复现厂商附加效果；完整上传原文件保留在登录保护的 original 接口。
- iPhone 网页相册不保证提供动态部分。可选择 HEIC/JPG 照片，再“补选配套 MOV/MP4”，手动配对，不会根据文件名猜测关联。HEIC 在服务端生成 JPEG 展示版本，上传原图保留。
- 未检测到动态时只提示未检测到，不把普通静态图假标成实况。勾选后缺少/损坏动态会拒绝保存，并清理本次文件；取消实况时内嵌 JPEG 动态会被移除，只保存静态照片。
- 每条记录仍最多 12 个附件；每个原图或配套视频 ≤100 MB，上传合计 ≤200 MB。动态最长 15 秒，单次转码限时 90 秒、2 个编码线程，同一进程一次处理一段；网页播放最长边 1280 像素，默认静音，可手动打开声音。
- 点击照片打开预览，点击 LIVE 或按住播放，松开停止；左右切换依旧按帖子浏览照片。
- 新增 media_extras 关联表，兼容旧数据库；删除帖子会清理原图、展示图和动态文件，所有媒体接口均要求登录。
- 真实 iPhone 资源和两台手机的相册传输链路尚待实测。无法从已变成静态 JPEG 的文件恢复动态。
- 测试：`PYTHONPATH=. pytest tests -q`；设置 `LIVE_SAMPLE=/path/to/original.jpg` 可额外验证私有 OPPO 样本（样本不进入 Git）。


### 纪念日
登录后通过 `/api/anniversaries` 读取相恋日与两位成员的公历生日（配置位于 `app/main.py`）。照片月历和全年热力图标记生日、每半年/周年、每 100 天；首页显示未来四项及倒计时，可点击跳转。相恋当天计第 0 天；日期差使用 UTC 日期运算，今天按 Asia/Shanghai 计算，页面每 30 秒及重新获得焦点时更新。多项纪念日同日保留全部；不生成帖子，不改变热力计数。当前不包含自定义纪念日编辑或推送通知。
日期测试：`node --test tests/anniversaries.test.mjs`。

### 帖子地点（腾讯地图 / 手动填写）
发布和编辑支持一个可选地点：名称、城市、地址、经纬度及坐标系。手动填写不需要 Key；修改名称或城市会清除原地图坐标，避免文字与坐标不一致。地图选点保存 GCJ-02 坐标，点击帖子地点打开腾讯地图；文字地点不虚构坐标。导出记录包含地点。新表 `entry_locations` 自动创建，旧帖子无需迁移，旧客户端编辑时不删除地点；新客户端检查原始地点以防并发覆盖。

启用地图选点：
1. 在腾讯位置服务 https://lbs.qq.com/dev/console/key/manage 创建用于网页地图组件的 Key，并按控制台要求开通相应服务。若设置 WebService 域名白名单，按照官方选点文档加入组件域名 `apis.map.qq.com`、跳转后的 `mapapi.qq.com` 及网站域名 `love.fefyjoey.xyz`（具体格式以控制台为准）。
2. 服务器项目目录的 `.env` 中添加或更新一行 `TENCENT_MAP_KEY=你的Key`，保留原来的 DOMAIN。Key 不提交 Git。该 Key 用于前端地图组件，登录成员能在网络请求中看到，应使用专用 Key 并设置适用的域名限制；不需要 SecretKey。
3. `sudo docker compose up -d --build`，刷新网页，发布或编辑中点“地图搜索 / 选点”。没有 Key 时仍可手动填写。

地图仅在主动打开选点窗口时加载。iframe 仅允许腾讯组件来源；消息同时校验 origin、source、模块和坐标，服务端再次校验。地图自行请求定位权限，拒绝后可搜索地点。地图服务无法访问时关闭窗口可手动填写，帖子草稿保留。当前 Key 未配置前无法验证手机上的真实地图服务、搜索和定位体验。

地图跳转兼容：选点服务会跳转到 `https://mapapi.qq.com`。CSP frame-src、iframe 定位授权和 postMessage origin 校验均显式允许这两个腾讯域名；仍检查消息必须来自当前 iframe，未放宽为任意域名。

### 对方动态与未读提醒
首页的“对方动态”在登录后及页面恢复前台时读取未读数量；页面可见且动态列表关闭时每 30 秒检查更新。动态列表按发布时间倒序显示，每次 50 条，可加载更早记录。点击某条动态跳转并定位到对应帖子/评论，同时标为已读；支持全部标为已读（只处理读取列表时已存在的动态，期间新增仍为未读）。打开列表本身不会清除未读。

只记录功能上线后另一位成员新发的帖子和新评论（含纯图片帖子和纯表情评论）；不补发历史消息，不记录编辑或表情回应。未读状态存储在 SQLite，换设备保持一致。发布和动态写入同一事务，失败不会产生提醒；删除帖子或评论会同步移除其对应动态。编辑帖子日期后，原动态会跳转到当前日期，摘要保留发布时的片段。新表 `activities` 自动创建，原记录不变。此功能为站内提醒，不发送系统推送、邮件或微信消息。
